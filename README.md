# Pagefolio

Windowsで動く、Webページを順番に画面保存して1つのPDFにまとめるデスクトップアプリです。Electron内のブラウザーでサイトを開き、スクロール・指定位置のクリック・キー操作でページを送ります。

## Windowsで使う

### GitHubから受け取る場合（Node.js不要）

GitHubの **Code → Download ZIP** からリポジトリを保存して、ZIPをすべて展開してください。展開先の **`Install-Pagefolio.cmd` をダブルクリック**すると、同梱の分割パッケージを結合し、SHA-256を照合してからアプリを展開・起動します。クラウドからPCへの直接転送は不要です。

既定の保存先はユーザーのOneDrive内の `仕事\開発\Pagefolio` です。確認画面で変更できます。保存先に既存ファイルがある場合は新しいサブフォルダーを作り、上書きを避けます。Node.js、Git、管理者権限は不要です。Windows用セットアップスクリプト自体はWindows実機で未検証です。

### アプリ単体のZIPを受け取った場合

1. `dist/Pagefolio-1.0.0-Windows-x64.zip` をダウンロードして**すべて展開**します。
2. 展開したフォルダー内の `Pagefolio.exe` を起動します。Node.jsのインストールは不要です。exeだけを移動せず、同梱ファイルと一緒に置いてください。
3. URLを入力し「サイトを開く」を押します。必要に応じてサイトに手動でログインし、保存を始めたい画面を表示します。
4. ページ送り方式を選びます。
   - **スクロール**：表示領域の中央にマウスホイール操作を送ります。画面の重なりを0〜40%で調整できます。
   - **クリック**：「位置を選ぶ」を押し、サイト上の「次へ」ボタンなどをクリックします。この位置選択ではページを送りません。選択後にウィンドウサイズを変えた場合は選び直してください。iframe内の選択ができない場合はキー操作をお試しください。
   - **キー操作**：右矢印・左矢印・Page Down・Spaceから選びます。あらかじめサイトの閲覧部分をクリックしてフォーカスを合わせてください。
5. 上限枚数（1〜500枚）と操作後の待ち時間（0.5〜60秒）を設定します。読み込みが遅いサイトでは待ち時間を長くします。
6. 「PDFに保存する」を押し、保存先を選びます。現在の画面を最初に保存し、以後はページ送りと保存を繰り返します。取得中はサイトを操作せず、ウィンドウを表示したままにしてください。
7. 同じ画面が連続した場合、上限枚数に達した場合、または停止ボタンを押した場合に終了し、取得済み画面をPDFにします。「保存先を開く」で結果を確認できます。

Windows 10 / 11 の64bit（x64）用です。このビルドはコード署名を行っていません。Windows実機での起動検証は未実施です。

## 保存内容と対応範囲

- **見えている範囲を1画面ずつ画像でPDF化**します。検索可能な文字データ、OCR、リンク、画面外の隠れたコンテンツは含みません。
- 最終ページを共通の方法で判定できるとは限りません。画像が同じ場合にもう一度待ってから終了しますが、読み込みが遅いサイトでは途中終了する可能性があります。待ち時間を増やしてやり直し、PDFの先頭・末尾を確認してください。
- 動画・時計・広告・点滅カーソルなどがあると画面が常に変わり、自動終了できないことがあります。上限枚数または停止ボタンを使用してください。
- 500画面を超えるものは分割して保存してください。PDF生成はメモリを使うため、高解像度画面では上限を下げてください。
- スクロールはブラウザー領域の中央が対象です。複雑な分割画面、複数のスクロール領域、特別なジェスチャーにはサイトごとの調整が必要です。
- サイトごとの認証・CAPTCHA・埋め込みブラウザーの制限によりログインできない場合があります。ポップアップのリンクは同じ表示領域で開きます。複数ウィンドウが必要な認証フローには未対応です。
- **Amazon Kindle Cloud Readerでの書籍取得は未検証です。** ログインやDRM・サイト側の保護により表示や画面取得ができない場合があります。DRM、アクセス制御、コピー保護を解除する機能は実装していません。
- 保存する権利のあるコンテンツに使用し、対象サイトの条件を確認してください。

## データの保存場所

PDFは選んだ場所に保存します。アプリから外部の変換サービスへ画像を送信しません。対象サイトへの通信は通常どおり発生します。

サイトのログイン情報（Cookie等）はElectronのユーザーデータ内に保存されます。Windowsの通常の場所は `%APPDATA%\pagefolio` です。共有PCではサイトからログアウトしてください。

画面取得中のJPEGはユーザーデータ内の `captures/run-*` に一時保存され、PDF作成成功後に削除されます。保存エラーや強制終了時は画像が残るので、アプリに表示される保管先から取り出せます。停止ボタンによる終了では取得済みの画面をPDFに保存します。

## ソースから起動・ビルド

Node.js 22.12以降とnpmをインストールし、リポジトリ直下で実行します。

```sh
npm ci
npm start
```

Windows用ZIPを生成：

```sh
npm run dist:win
```

依存パッケージとElectronの取得に `registry.npmjs.org`、`github.com`、GitHubのリリース配布先への通信が必要です。自動公開は設定していません。

## テスト

```sh
npm test
npm run test:desktop
```

`npm test` はURL・入力検証、保存順、遅延描画、上限、途中停止、部分保存を検証します。`test:desktop` は実際のElectronとローカルHTTPサーバーを使い、スクロール・クリック位置指定・キー操作、PDFページ数、停止・ダイアログ取消、サイトとアプリの権限分離を検証します。GUI環境が必要です。出力PDFとスクリーンショットは `test-results/` に作成します。

クラウドでの検証はLinux + 仮想ディスプレイで実施しました。コンテナーの制約上、そのローカルテストに限って `--no-sandbox` を使用しました。通常起動・Windows配布物ではサンドボックスを無効化していません。テストは外部サイトへ接続せず、Amazonアカウントや書籍は使用しません。

## 構成

- `src/main.cjs`：Electron、分離ブラウザー、ページ操作、保存制御
- `src/core.cjs`：設定検証、取得ループ、PDF生成
- `src/preload.cjs`：アプリ画面だけに公開するIPC
- `src/index.html` / `styles.css` / `renderer.js`：日本語UI
- `test/`：単体テストと実ブラウザーの統合テスト

既存の `/workspace/sampletest` をそのまま利用できます。クラウドタスクは隔離されているので、作業ツリーの追加作成は不要です。
