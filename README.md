# Pagefolio 1.1

Windowsで動く、Webページを順番に画面保存してPDFにまとめるデスクトップアプリです。個別保存、Kindleの絞り込み済み一覧からの一括保存、複数Web URLの一括保存に対応します。枚数上限はなく、末尾検出または手動停止まで続けます。既定の操作後待ち時間は0.5秒です（描画・読み込み・保存に必要な時間は別途かかります）。

## Windowsで使う

### GitHubから受け取る場合（Node.js不要）

GitHubの **Code → Download ZIP** からリポジトリを保存して、ZIPをすべて展開してください。展開先の **`Install-Pagefolio.cmd` をダブルクリック**すると、同梱の分割パッケージを結合し、SHA-256を照合してからアプリを展開・起動します。クラウドからPCへの直接転送は不要です。

既定の保存先はユーザーのOneDrive内の `仕事\開発\Pagefolio` です。確認画面で変更できます。保存先に既存ファイルがある場合は新しいサブフォルダーを作り、上書きを避けます。Node.js、Git、管理者権限は不要です。Windows用セットアップスクリプト自体はWindows実機で未検証です。

### アプリ単体のZIPを受け取った場合

1. `dist/Pagefolio-1.1.0-Windows-x64.zip` をダウンロードして**すべて展開**します。
2. 展開したフォルダー内の `Pagefolio.exe` を起動します。Node.jsのインストールは不要です。exeだけを移動せず、同梱ファイルと一緒に置いてください。
3. URLを入力し「サイトを開く」を押します。必要に応じてサイトに手動でログインし、保存を始めたい画面を表示します。
4. ページ送り方式を選びます。
   - **スクロール**：表示領域の中央にマウスホイール操作を送ります。画面の重なりを0〜40%で調整できます。
   - **クリック**：「位置を選ぶ」を押し、サイト上の「次へ」ボタンなどをクリックします。この位置選択ではページを送りません。選択後にウィンドウサイズを変えた場合は選び直してください。iframe内の選択ができない場合はキー操作をお試しください。
   - **キー操作**：右矢印・左矢印・Page Down・Spaceから選びます。あらかじめサイトの閲覧部分をクリックしてフォーカスを合わせてください。
5. 操作後の待ち時間（0.5〜60秒、初期値0.5秒）を設定します。読み込みが遅いサイトでは待ち時間を長くします。枚数指定は不要です。
6. 「PDFに保存する」を押し、保存先を選びます。現在の画面を最初に保存し、以後はページ送りと保存を繰り返します。取得中はサイトを操作せず、ウィンドウを表示したままにしてください。
7. スクロールの末尾、次へボタンの無効化、画面の変化停止、ページの循環を検出すると終了し、取得済み画面をPDFにします。停止ボタンでもここまでの分を保存できます。ファイル名の初期値はページタイトルです。

Windows 10 / 11 の64bit（x64）用です。このビルドはコード署名を行っていません。Windows実機での起動検証は未実施です。

## Kindle一覧の一括保存

1. **Kindle一括 → Kindleライブラリを開く**を押し、手動でログインします。
2. サイト内でフィルター・検索・並べ替えを設定し、行表示にします。対象は現在の絞り込み済み一覧です。
3. **絞り込み済み一覧を読み取る**を押します。一覧をスクロールして、表示DOMからタイトルとASINを集め、重複を除きます。遅延読み込みを待ち、読み取り後に元のスクロール位置へ戻します。
4. 左側のタイトル一覧を確認し、不要な本のチェックを外します。PDF名はこの一覧のタイトルを使用します。
5. 開始位置は**本の先頭**か**前回の読書位置**を選びます。先頭を選んだ場合、本文が表示された後にサイトの「本の先頭／表紙／Beginning」等の操作を試みます。対応する操作を確認できない本は保存を始めずエラーとして記録します。
6. ページ送り方向を選びます。既定は右矢印です。縦書きなど左矢印で進む本は左矢印に変更してください。同じ一括処理では全冊に同じ送り方を使います。読み方向が混在する場合は分けて実行してください。
7. **選択した対象を一括保存**で保存先フォルダーを選択します。元の一覧を残した別の閲覧領域で、`https://read.amazon.co.jp/?asin=...` を1冊ずつ開きます。ログインセッションは共有します。

同名の本や既存PDFには `(2)`、`(3)` のように番号を付け、上書きを防ぎます。Windowsで使えない記号は `_` に置換します。各本の結果は一覧と保存先の `Pagefolio-result-*.json` に残ります。

**Kindleの実サイト／実アカウントでの動作は未検証です。** ASINを公開DOMから取得できないサイト構造、別ドメインのiframe、対応外のリーダー、DRMなどでは一覧や本文を取得できません。一覧に0冊しか出ない場合は、行表示・ログイン状態を確認してください。絞り込み内容が変わった場合は一覧を再読込してください。サイト側で遅延読み込みに時間がかかる場合やページ分割されている場合、読み取り件数と実際の対象件数を確認してください。

## Webサイトの一括保存

1. **Web一括**を選び、URLを1行ずつ貼り付けます。
2. **URLを一覧に登録**を押し、対象を確認します。同じURLは重複登録しません。
3. 送り方と待ち時間を指定し、**選択した対象を一括保存**で保存先を選びます。既定の送り方はスクロールです。

PDF名には読み込んだページのタイトルを使います。任意の名前を付ける場合は `タイトル［タブ文字］URL` の形式で入力できます。ログインが必要なサイトは先にURL欄から開いてログインしてください。クリック方式の一括では全サイトに同じクリック位置を使うため、サイトごとにレイアウトが異なる場合は個別実行してください。クリック方式の詳細設定で「次へ」ボタンのCSSセレクターも指定できます。

保存に失敗した対象はエラーとして記録し、次へ進みます。認証不足を検出したKindle、ディスク容量不足、書き込み権限エラーは処理を停止します。停止ボタンは現在の対象の取得済み分を保存し、後続は未実行のまま残します。再開始するとチェックされた全対象を再実行します。再開したい対象だけをチェックしてください。

## 保存内容と対応範囲

- **見えている範囲を1画面ずつ画像でPDF化**します。検索可能な文字データ、OCR、リンク、画面外の隠れたコンテンツは含みません。
- 最終ページを共通の方法で確定できるとは限りません。変化がない場合は追加で3回待ちますが、読み込みが遅いサイトでは途中終了する可能性があります。画面比較・循環で終了した一括PDFは**末尾要確認**となります。待ち時間を増やすか操作方向を直し、PDFの先頭・末尾を確認してください。
- スクロールでは位置とコンテンツの高さも比較するので、時計等が動いても末尾を検出できます。キー・クリック操作で常に変化する画面や無限スクロールでは、終了を判定できない場合があります。その場合は停止ボタンを使ってください。
- 500画面で停止する制限は撤廃しました。PDFは逐次書き込みし、遅いディスクに合わせてバッファを制限します。取得画像と出力PDFのための空きディスク容量は必要です。
- スクロールはブラウザー領域の中央が対象です。複雑な分割画面、複数のスクロール領域、特別なジェスチャーにはサイトごとの調整が必要です。
- サイトごとの認証・CAPTCHA・埋め込みブラウザーの制限によりログインできない場合があります。ポップアップのリンクは同じ表示領域で開きます。複数ウィンドウが必要な認証フローには未対応です。
- **Amazon Kindle Cloud Readerでの書籍取得は未検証です。** ログインやDRM・サイト側の保護により表示や画面取得ができない場合があります。DRM、アクセス制御、コピー保護を解除する機能は実装していません。
- 保存する権利のあるコンテンツに使用し、対象サイトの条件を確認してください。

## データの保存場所

PDFは選んだ場所に保存します。アプリから外部の変換サービスへ画像を送信しません。対象サイトへの通信は通常どおり発生します。

サイトのログイン情報（Cookie等）はElectronのユーザーデータ内に保存されます。Windowsの通常の場所は `%APPDATA%\pagefolio` です。共有PCではサイトからログアウトしてください。

画面取得中のJPEGはユーザーデータ内の `captures/run-*` に一時保存され、PDF作成成功後に削除されます。保存エラーや強制終了時は画像が残るので、アプリに表示される保管先から取り出せます。停止ボタンによる終了では取得済みの画面をPDFに保存します。

## ソースから起動・ビルド

Node.js 22.12以降とnpmをインストールし、リポジトリ直下で実行します。

```sh
npm ci
npm start
```

Windows用ZIPを生成：

```sh
npm run dist:win
```

GitHubのDownload ZIPに含める分割配布物を更新する場合は、ビルド後に `npm run package:download` を実行します。現在のバージョンのZIPから `windows-package/` とSHA-256付きのmanifestを生成します。

依存パッケージとElectronの取得に `registry.npmjs.org`、`github.com`、GitHubのリリース配布先への通信が必要です。自動公開は設定していません。

## テスト

```sh
npm test
npm run test:desktop
```

`npm test` はURL・入力検証、510ページの取得、保存順、遅延描画、循環停止、部分保存、ファイル名・重複保護を検証します。`test:desktop` は実際のElectronとローカルHTTPサーバーを使い、スクロール・クリック・キー操作、PDF内容・枚数、Web一括と停止、HTTPエラー後の継続を検証します。KindleはHTTPS通信をローカルの模擬DOMに置き換え、絞り込み、遅延一覧、ログイン状態の共有、先頭移動、末尾・未対応の本の処理を検証します。GUI環境が必要です。出力PDFとスクリーンショットは `test-results/` に作成します。

クラウドでの検証はLinux + 仮想ディスプレイで実施しました。コンテナーの制約上、そのローカルテストに限って `--no-sandbox` を使用しました。通常起動・Windows配布物ではサンドボックスを無効化していません。テストは外部サイトへ接続せず、Amazonアカウントや書籍は使用しません。

## 構成

- `src/main.cjs`：Electron、分離ブラウザー、ページ操作、保存制御
- `src/core.cjs`：設定検証、取得ループ、PDF生成
- `src/batch-controller.cjs`：一覧収集、一括キュー、別閲覧領域、結果レポート
- `src/batch.cjs` / `src/page-scripts.cjs`：URL・ファイル名、公開DOMの読み取りとページ操作
- `src/preload.cjs`：アプリ画面だけに公開するIPC
- `src/index.html` / `styles.css` / `renderer.js`：日本語UI
- `test/`：単体テストと実ブラウザーの統合テスト

既存の `/workspace/sampletest` をそのまま利用できます。クラウドタスクは隔離されているので、作業ツリーの追加作成は不要です。
